# 3 (ทางเลือก) แบ่ง region / ตาราง / ช่อง: คำสั่ง `regions`

ขั้น 3 อีกแบบหนึ่ง ข้าง ๆ ผัง section เดิม ([03-sections.md](03-sections.md)) ย้ายเทคนิคมาจาก `learning/preprocess_finance` แล้วต่อเข้ากับ pipeline นี้
ผลแยกเป็น **region** (ส่วนของหน้า), **ตาราง → ช่อง** (r00 = หัวตาราง) และ **คู่ key/value** ตามตำแหน่ง พร้อมภาพแต่ละขั้นและ `manifest.json`

- ภาพล้วน ใช้ CPU ไม่เรียก OCR (18 ใบ: รวม `elapsed_s` ใน manifest = 8.7 วินาที ไม่นับเวลาโหลดภาพ final)
- **ไม่แตะผังเดิมและผล OCR ที่มีอยู่**: ผลอยู่ในโฟลเดอร์ `regions/` แยกต่างหาก ผัง section เดิมยังเป็นค่าตั้งต้นของ flow หลัก
- ต่อเข้า OCR ได้ด้วย `sections --layout regions` (ไม่ใช่ค่าตั้งต้น) **วัดแล้วแย่กว่าผัง section เดิม** (ดูหัวข้อ "ผลวัดกับ OCR")

```bash
python -m fin_extractor sections data/01_input/finance_doc_scan --to preprocess   # ต้องมีภาพ final ของขั้น 2 ก่อน
python -m fin_extractor regions  data/01_input/finance_doc_scan                   # ทุกไฟล์ + summary.json + contact_sheet.png
python -m fin_extractor regions  data/01_input/finance_doc_scan --only 1307 1313  # บางไฟล์
python -m fin_extractor regions  data/01_input/finance_doc_scan --no-debug-images # เหลือแค่ crops/ + manifest.json
python -m fin_extractor sections data/01_input/finance_doc_scan --layout regions --from layout   # OCR + สกัดจากภาพ region → <engine>/regions-luma/
python -m fin_extractor compare  data/01_input/finance_doc_scan --variants luma regions-luma     # เทียบกับผัง section
```

## ผลอยู่ที่ไหน

```
data/03_sections/<dataset>/<profile>/regions/
├── contact_sheet.png                  overlay ทุกใบในภาพเดียว (เริ่มดูที่นี่)
├── summary.json                       ต่อไฟล์: ชนิดเอกสาร, โหมด, ชื่อ region, จำนวนตาราง/ช่อง/kv, QR ที่ถอดได้
└── <ไฟล์>/
    ├── 01_normalize.png               หน้าที่ตัดเหลือขอบเขตเนื้อหา (สำเนา 200 dpi)
    ├── 02_mask.png                    ระบาย QR/บาร์โค้ด/ลายเซ็น (มีเฉพาะเมื่อเจอ)
    ├── 03_clean.png                   ลบลายน้ำสี (มีเฉพาะไฟล์ที่ตั้ง clean)
    ├── 04_regions.png                 region (สีละกล่อง) + เส้นนอนที่เจอ (ม่วง)
    ├── 05_tables.png                  เส้นตั้ง (ส้ม) หัวตาราง (แดง) ช่องค่า (เขียว)
    ├── crops/<ลำดับ>_<region>[_tNN]__<วิธี>.png         ภาพแต่ละ region (tNN = ท่อนเมื่อสูงเกิน)
    ├── crops/tables/t<T>_r<RR>_c<CC>__<วิธี>.png        ช่องตาราง: ตาราง T แถว RR (r00 = หัว) คอลัมน์ CC
    ├── manifest.json                  ค่าที่ตรวจได้ทุกขั้น + files[] + kv_pairs
    ├── sections.json                  ผังในรูปเดียวกับ layout/<ไฟล์>.json ให้ขั้น OCR รายส่วนอ่าน (เฉพาะ region ไม่รวมช่องตาราง)
    └── crops/index.json               ภาพ region แบบ luma ที่ส่งเข้า OCR (เหมือน images/<วิธี>/<ไฟล์>/index.json)
```

ทุกครั้งที่รัน ภาพขั้นและ `crops/` ของไฟล์นั้นถูกล้างก่อนเขียนใหม่ ไฟล์ในโฟลเดอร์จึงตรงกับ `manifest.json` เสมอ

ใน `manifest.json → stages.export`:
- `files[]`: ภาพ crop ทุกไฟล์ มีกล่อง 2 แบบ
  - `box` คือพิกัดบนสำเนา normalize 200 dpi (ตรงกับภาพ 01–05)
  - `box_page` คือพิกัดบนภาพ final ของขั้น 2 ความละเอียดเต็ม ใช้ map กลับไปที่หน้าได้
- `kv_pairs[]`: ช่องค่าแต่ละช่องมี key ผู้สมัคร 2 แบบ
  - `header_key_crop` คือหัวคอลัมน์ที่ทับแนว x มากที่สุด
  - `left_key_crop` คือช่องทางซ้ายในแถวเดียวกัน (แถวแบบ ป้าย | ค่า)
  - ตัดสินว่าใช้ key ไหนหลัง OCR
- `stages.mask.codes[]`: QR/บาร์โค้ดที่เจอพร้อม `data` ที่ถอดได้ ค่านี้ตรงตัว ไม่ผ่าน OCR เช่น 1312 ได้เลขเอกสาร `BI8461-101069` จาก QR

## ลำดับงาน

ขั้น 1–2 ใช้ของ pipeline นี้: โหลด PDF render 300 dpi, หมุนด้วยตัวจำแนกทิศของ Paddle (แยก 90° กับ 270° ได้ ซึ่ง preprocess_finance ทำไม่ได้) และแก้เอียง
คำสั่ง `regions` เริ่มจากภาพ `02_preprocess/…/final/`

| ขั้น | ทำอะไร | โค้ด (`sections/regions/`) |
|---|---|---|
| ย่อ | ย่อภาพ final เป็นสำเนา 200 dpi เพราะค่า px ทุกตัวใน `configs/regions/pipeline.yaml` วัดที่ 200 dpi | `run.py` |
| normalize | ตัดเหลือขอบเขตหมึก + ขอบ 1% ทิ้งเงาขอบสแกน เพื่อให้ ratio ของ template ไม่ขึ้นกับขอบสแกน | `geometry.content_bbox` |
| mask | หา QR (บล็อกจัตุรัสหมึกหนาแน่น) / บาร์โค้ด (ขอบแนวตั้งเด่น) → ถอดรหัส → ระบายขาว บวกพื้นที่ `ignore` ของ template (ลายเซ็น ตรายาง) | `codes.py` |
| clean | ลบลายน้ำสีรายไฟล์ (`suppress_color` ของ 1308/1309) เป็นสำเนาแยก ใช้ทำ crop แบบ `__clean` เท่านั้น | `preprocessing/clean.suppress_color` |
| regions | ฟอร์มตายตัว (50 ทวิ): ratio ใน template แล้วดูดขอบบน/ล่างเข้าหาเส้นจริง · เอกสารอื่น: ตัดเป็นแถบตามเส้นนอน ไม่ตัดผ่านข้อความข้างเส้นสั้น (เส้นน้อยกว่า 3 เส้น = แบ่งตามช่องว่าง) | `split.py`, `lines.py` |
| tables | เส้นตั้ง → ช่องของแต่ละแถบ → รวมแถบที่คอลัมน์ตรงกันเป็นตาราง → แถวรายการที่ไม่มีเส้นคั่นแยกด้วยคอลัมน์ anchor → แถวแรก = หัว | `tables.py` |
| export | ตัด crop ให้เหลือแต่ข้อความ (`trim_box`) → region ที่สูงเกิน 0.3 ของหน้าตัดเป็นท่อนที่แถวว่าง → ตัดจาก **ภาพ final สีความละเอียดเต็ม** | `run.py` |

รายละเอียดของแต่ละกฎ (ทำไมต้องเป็นแบบนี้ และเจอกับไฟล์ไหน) มีในคอมเมนต์ของโค้ดและใน `learning/preprocess_finance/docs/preprocessing.md`

### สิ่งที่ไม่ได้ย้ายมา หรือเปลี่ยนไป
- **orient / deskew / ลบเส้นสกปรก** ทำในขั้น 2 อยู่แล้ว
  - ตัวลบเส้นสกปรกย้ายมาจากที่เดียวกันก่อนหน้านี้แล้ว (`preprocessing/clean.remove_streaks` ยังไม่เปิดเป็นค่าตั้งต้น)
  - ผลข้างเคียง: เส้นสกปรกของ 1320/1322 ยังอยู่ ขอบเขตเนื้อหาจึงกว้างกว่าของ preprocess_finance (1547 กับ 1323 px) จำนวน region เท่ากัน
- **ตัดท่อนของ region สูง**: preprocess_finance ใช้ `tile_on_whitespace` (900 px ซ้อนกัน 20 px ยังไม่ได้วัดกับ OCR)
  - ที่นี่ใช้ตัวตัดของโหมดนี้เอง (`sections/regions/pieces.py`) เพดาน `max_piece_frac` 0.3 ยืมค่ามาจากผลวัดกับ OCR ของผัง section เดิม ([03-sections.md](03-sections.md) หัวข้อผลวัด) ดูหัวข้อ "ตัด region สูงเป็นท่อน"
  - template ตั้ง `tile: false` ปิดการตัดรายกรอบได้ (ตอนนี้ไม่มีกรอบไหนตั้ง: ตารางรายได้ 50 ทวิรวมเป็น `income_table` แล้วตัดตามแถว)
- **วิธีเตรียมภาพ crop** ใช้ชื่อเดียวกับภาพ section คือ `color | luma | flat | bin`
  - ค่าตั้งต้น `luma` อย่างเดียว เพราะวัดแล้วดีสุดกับ OpenThai
  - preprocess_finance ส่งออก raw/gray/binary ซึ่งยังไม่ได้วัดกับ OCR
  - เพิ่มวิธีได้ที่ `export.variants` / `export.cell_variants`

## Template กับ `doc_types.yaml`

- `configs/regions/doc_types.yaml` **ผูกชนิดเอกสารกับชื่อไฟล์ของสแกน 18 ใบนี้ ไม่ใช่ตัวจำแนก**
  - 1307/1321/1323 → `wht_50tawi`, 1311 → `wht_50tawi_v2`, 1308/1309 → ลบลายน้ำ
- ไฟล์ที่ไม่อยู่ในตารางเป็น `generic` (แบ่งตามเส้น ไม่ต้องตั้งค่า) เอกสารใหม่จึงยังได้ region/ตาราง แต่ไม่ได้ชื่อฟิลด์จาก template
- ถ้าจะใช้กับเอกสารจริงที่ไม่รู้ชื่อไฟล์ล่วงหน้า ต้องมีตัวจำแนกชนิดมาแทน `doc_types.classify` (ขั้นอื่นไม่ต้องแก้)
- `configs/regions/templates/*.yaml` คือกรอบ ratio ของ 50 ทวิ
  - ratio วัดเทียบกับขอบเขตเนื้อหาของหน้าที่ normalize แล้ว
  - วัดบน 1307/1321 และตรวจกับ 1311/1323 ใน preprocess_finance

## ตัด region สูงเป็นท่อน (`sections/regions/pieces.py`)

รุ่นแรกตัดด้วย `sections.layout.split_rows` ของผัง section เดิม: ตัดที่แถวว่างที่ใกล้จุดแบ่งเท่า ๆ กันที่สุด ทำให้ตารางหลักถูกตัดครึ่ง 16 จาก 18 ใบ
- 1306: บรรทัดสุดท้ายของคำอธิบายรายการ ("จำนวน 26-40 บิล ...") หลุดไปอยู่ท่อนที่สองคนเดียว ใต้มันเป็นตารางว่างยาว
- สาเหตุซ้อน: เศษเส้นตารางที่ลบไม่หมด (สูง 1–3 px) ทำให้ `trim_box` หดขอบไม่ลง region จึงสูงเกินจริง (ตาราง 1306 ข้อความจริงสูง 0.17 ของหน้า แต่กรอบสูง 0.40)

ตอนนี้ทุก region ที่ไม่ได้ปิด `tile` ผ่านขั้นนี้:
1. **หาช่วงแถวที่มีหมึก**
   - หมึก = Otsu ∪ ระยะสีจากพื้น (`sections.images.binarize_inverted`) แล้วลบเส้นตารางออก
   - ใช้ Otsu อย่างเดียวไม่ได้ เพราะมองไม่เห็นตัวพิมพ์สีอ่อน รุ่นทดลองหดทิ้งรายการสินค้าของ 1319 ทั้งแถว
   - ระบายแถบ ±6 px รอบเส้นตั้ง และทิ้งเศษเส้นแบบ `tables._no_slivers`
   - ช่วงที่สูง ≤ 2 px คือเศษเส้น (เกณฑ์เดียวกับ `trim_box`) ช่วงที่สูงถึง 12 px (`tables.min_row_h`) นับเป็นบรรทัด
2. **หดขอบบน/ล่าง** ให้เหลือจากหมึกแรกถึงหมึกสุดท้าย (+6 px) ไม่สูงเกินเพดานก็ไม่ตัด
3. **จุดตัด**
   - ถ้ามีเส้นตั้งด้านในและบรรทัดที่มีข้อความในคอลัมน์ซ้ายสุด ≥ 2 บรรทัด (เลขข้อ/รหัสสินค้า) ตัดได้เฉพาะก่อนบรรทัดเหล่านั้น (`items`)
   - ไม่งั้นตัดได้ทุกช่องว่างระหว่างช่วงหมึก (`gaps`)
4. **เลือกจุดตัด** จากบนลงล่าง
   - เลือกช่องว่างที่กว้างที่สุดในช่วงที่ท่อนสูงครึ่งถึงเต็มเพดาน (ช่องว่างระหว่างรายการหรือย่อหน้ากว้างกว่าระหว่างบรรทัดในรายการเดียวกัน)
   - ห้ามท่อนเตี้ยกว่าครึ่งเพดาน แบบที่ `tile_on_whitespace` ของ preprocess_finance ทำ เพื่อไม่แยกหัวตารางเป็นท่อนเล็ก (1317/1318)
   - ไม่มีจุดในช่วงก็ใช้จุดแรกที่เลยไป ท่อนสูงเกินดีกว่าตัดกลางรายการ
5. **หดขอบทีละท่อน** ตามหมึกของท่อนนั้น

## ผลวัดกับ OCR (OpenThai, 18 ใบ, rules ล้วน ไม่มีเฉลย)

`sections --layout regions` อ่าน **เฉพาะภาพ region** (ไม่อ่านช่องตาราง เพราะข้อความของช่องอยู่ในแถบเดียวกันแล้ว) ตามลำดับ
region ที่สูงเกิน 0.3 ของหน้าถูกตัดเป็นท่อน (ดูหัวข้อก่อนหน้า) ผลอยู่ที่ `04_ocr/…/openthai/regions-luma/` และ `05_extract/…/openthai/regions-luma/rules/`

รอบแรก template ของ preprocess_finance แยกตารางรายได้ 50 ทวิเป็น 4 คอลัมน์:
- ภาพคอลัมน์ตัวเลขไม่มีป้ายกำกับ OpenThai จึงตอบเป็นตารางว่างหลายสิบแถว (1321 `income_tax` ยาวราว 200 บรรทัด)
- 50 ทวิทั้ง 4 ใบตกเป็น failed

รอบสองรวมเป็น region เดียว `income_table` (ขอบเขตรวมของ 4 คอลัมน์เดิม ตัดเป็นท่อนตามแถวด้วย `max_piece_frac`):
- 1307 ฟิลด์ขาด 3 → 1 และ 1311 ขาด 2 → 0 กลับเป็น needs_review
- 1321/1323 ยัง failed เพราะยอดรวมอ่านได้เป็น `106,250 .00`
  - ฟอร์มพิมพ์บาทกับสตางค์ในช่องแยกกัน OCR จึงใส่ช่องว่างหรือแยกเป็นสองช่องตาราง rules จึงหายอดรวมไม่เจอ
  - 1323 ไม่ถูกจัดเป็น 50 ทวิด้วย (ขาด `invoice_no`, `total_amount` ซึ่งเป็นฟิลด์ของใบกำกับภาษี)
  - ปัญหานี้อยู่ที่ขั้นสกัด (rules) ไม่ใช่การแบ่ง region

ไฟล์อื่น:
- **1306** failed: กล่องยอดรวมอ่านแยกป้ายกับตัวเลขออกจากกัน (ป้ายเป็นบรรทัด ตัวเลขเป็นตาราง) rules จับคู่ไม่ได้

## ยังไม่ได้ทำ / ข้อจำกัด

- วัดกับ OCR แค่ OpenThai และอ่านเฉพาะ region ยังไม่ได้ลองอ่านทีละช่องตาราง หรือใช้ Typhoon
- ข้อจำกัดที่ preprocess_finance บันทึกไว้ยังอยู่:
  - เส้นตารางสีอ่อนของ 1317–1319 หาไม่เจอ ตารางสินค้าจึงยังไม่ถูกแบ่งเป็นช่อง
  - ลายเซ็นในโหมด generic ไม่ถูกตัด
  - 1313/1314 มีหัวตารางชุดที่สองกลางตารางที่ถูกนับเป็นแถวค่า
  - 311 สแกนขาดขอบขวา
- ขนาดผล: ทั้ง 18 ใบ 207 MB แบ่งเป็นภาพขั้น 01–05 157 MB และ `crops/` 45 MB ใช้ `--no-debug-images` เมื่อไม่ต้อง debug
