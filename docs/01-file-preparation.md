# ขั้นที่ 1: เตรียมและโหลดไฟล์

โค้ด: `src/fin_extractor/io/loader.py`

วางเอกสารต้นฉบับไว้ใน `data/raw/` แล้วสั่งรันได้ทั้งทีละไฟล์หรือทั้งโฟลเดอร์
ระบบจะแปลงทุกไฟล์เป็นภาพ 1 ภาพต่อ 1 หน้า แล้วทำขั้นที่ 2–7 แยกทีละหน้า

## หลักการ

แปลงไฟล์ทุกชนิดให้อยู่ในรูปเดียวกันคือ **ภาพทีละหน้า** ขั้นถัดไปจะได้ไม่ต้องสนใจว่าต้นทางเป็นรูปถ่าย
ภาพสแกน หรือ PDF

นี่เป็นการตัดสินใจออกแบบ: **ทุกไฟล์ถือเป็นภาพ แล้วอ่านด้วย OCR** แม้แต่ PDF ที่มีข้อความฝังอยู่แล้ว
เหตุผลและสิ่งที่แลกอยู่ใน [README](README.md#หลักการออกแบบ)

## ไฟล์ที่รองรับ

| ชนิด input | นามสกุล | ระบบทำอะไร |
|---|---|---|
| ภาพ | `.jpg` `.jpeg` `.png` `.tif` `.tiff` `.bmp` `.webp` | อ่านเป็นภาพสี (BGR, uint8) 1 หน้า |
| PDF | `.pdf` | render ทีละหน้าเป็นภาพที่ 300 DPI ด้วย `pypdfium2` (ปรับได้ที่ `loader.pdf_dpi`) |
| โฟลเดอร์ | — | ไล่หาทุกไฟล์ที่รองรับ รวมถึงโฟลเดอร์ย่อย เรียงตามชื่อ |

## ขั้นตอนภายใน

1. **ตรวจ input** (`iter_input_files`): ถ้าเป็นไฟล์ก็ใช้ไฟล์นั้น ถ้าเป็นโฟลเดอร์ให้ค้นแบบ recursive แล้วกรองตามนามสกุล
2. **โหลดตามชนิดไฟล์** (`load_pages`):
   - ภาพ: `np.fromfile` → `cv2.imdecode`
   - PDF: render แต่ละหน้าด้วย scale = DPI / 72 → แปลง RGB เป็น BGR
3. **ส่งต่อ:** คืน list ของภาพไปให้ pipeline โดยหน้าที่ 1 คือ `_p1`, หน้าที่ 2 คือ `_p2` ไปเรื่อย ๆ

## ข้อควรรู้ก่อนเตรียมไฟล์

- **ชื่อไฟล์ภาษาไทยใช้ได้** เพราะระบบไม่ใช้ `cv2.imread` ซึ่งบน Windows อ่าน path ภาษาไทยไม่ได้
- **ความละเอียด** สแกนที่ 200–300 DPI ดีที่สุด ถ้าภาพเล็กกว่าเกณฑ์ ขั้นที่ 2 จะขยายให้เอง แต่การขยายไม่ช่วยกู้รายละเอียดที่หายไปแล้ว
- **ภาพถ่ายมือถือ** ใช้ได้ แต่ควรถ่ายตรง ไม่มีเงาบัง ระบบแก้เอียงได้ไม่เกิน ±15° และแก้กลับหัว/ตะแคงได้
- **PDF ที่มี text layer** (PDF ที่สร้างจากโปรแกรม) ถูก render เป็นภาพแล้ว OCR เหมือนไฟล์อื่น ไม่ดึงข้อความตรง ๆ (ตั้งใจ — ดูหัวข้อถัดไป)
- **ตรวจชนิดไฟล์จากนามสกุล** ไม่ได้ดูจากเนื้อไฟล์ (magic bytes) ถ้ามีคนเปลี่ยนนามสกุลไฟล์อื่นเป็น `.pdf` จะไปล้มตอนเปิดไฟล์ ไม่ได้ถูกปฏิเสธตั้งแต่ต้น
- **ข้อมูลจริงไม่ถูก commit:** `.gitignore` กันทุกอย่างใต้ `data/` ไว้ (เก็บเฉพาะ `.gitkeep`) เพราะเอกสารมีเลขภาษีและข้อมูลส่วนบุคคล

## PDF ที่ข้างในเป็นภาพ

นามสกุล `.pdf` เหมือนกัน แต่ข้างในมีได้สามแบบ

| แบบ | มาจาก | ข้างในมีอะไร |
|---|---|---|
| PDF ดิจิทัล | export จากโปรแกรม (Word, ระบบบัญชี) | ข้อความจริง (text layer) ไม่มีภาพ |
| **PDF สแกน** | เครื่องสแกน หรือแปลงรูปถ่ายเป็น PDF | **ภาพเต็มหน้า 1 รูป** ไม่มีข้อความเลย |
| PDF สแกนที่ทำ OCR แล้ว | สแกนเนอร์บางรุ่น, Adobe "ทำให้ค้นหาได้" | ภาพเต็มหน้า + ข้อความที่ OCR ฝังซ้อนไว้ |

ตัวอย่างที่เปิดดูข้างในด้วย `pypdfium2`

```
PDF สแกน (แปลงจาก BITKUB-001.jpg)
  text layer: 0 ตัวอักษร   ภาพที่ฝัง: 1 รูป
  ภาพ 1000x1050 px คลุม 100% ของหน้า ≈ 150 DPI ต้นฉบับ

PDF ดิจิทัล (VATGB-001.pdf)
  text layer: 746 ตัวอักษร   ภาพที่ฝัง: 0 รูป
```

### ระบบทำอะไรกับ PDF สแกน

render ทุกหน้าเป็นภาพเสมอ ไม่ว่าข้างในจะเป็นข้อความหรือภาพ PDF สแกนจึง **ใช้ได้ทันทีโดยไม่ต้องทำอะไรเพิ่ม**
ภาพที่ได้เหมือนภาพที่ฝังอยู่ แล้วเข้า preprocess และ OCR เหมือนไฟล์ `.jpg`

```
PDF สแกน → pypdfium2 render เป็นภาพ (300 DPI) → preprocess → OCR → ...
```

### render ที่ 300 DPI ไม่ได้ทำให้ภาพสแกนชัดขึ้น

ความละเอียดของ PDF สแกนถูกกำหนดตั้งแต่ตอนสแกน ถ้าสแกนมา 150 DPI การ render ที่ 300 คือการยืดภาพ
ด้วยการเดาพิกเซลระหว่างกลาง ภาพใหญ่ขึ้นแต่ข้อมูลเท่าเดิม

| render | ขนาดที่ได้ | เวลา |
|---|---|---|
| 150 DPI (= ต้นฉบับ) | 1001 × 1050 px | 52 ms |
| 300 DPI (ค่าตั้งต้น) | 2001 × 2100 px | 93 ms |

ไม่ถึงกับเป็นปัญหา เพราะขั้นที่ 2 ขยายภาพเล็กอยู่แล้ว แต่ถ้าต้องการคุมให้ดีกว่านี้มีสองทาง
- render ที่ DPI ต้นฉบับ (ขนาดภาพเป็น px ÷ ขนาดบนหน้าเป็นนิ้ว)
- ดึงภาพที่ฝังอยู่ออกมาตรง ๆ จะได้ภาพต้นฉบับโดยไม่ผ่านการวาดซ้ำ

### ทำไมไม่อ่าน text layer ตรง ๆ

การอ่านข้อความจาก PDF ดิจิทัลตรง ๆ เร็วกว่า OCR มาก (โปรเจกต์รุ่นก่อนวัดได้ราว 1 วินาที เทียบกับ OCR
ราว 20 วินาที และถูกครบ 5/5 ค่า) แต่ต้องแยก **PDF สแกนที่ทำ OCR แล้ว** ออกให้ได้ เพราะข้อความที่ฝังไว้
อาจผิดทั้งที่ไฟล์ดูเหมือนมีข้อความครบ

โปรเจกต์รุ่นก่อนเจอกับเอกสารกรมสรรพากร **ทุกฉบับที่ทดลอง (32 หน้า)**

| อาการ | ตัวอย่าง |
|---|---|
| สระถูกฉีกจากพยัญชนะ | `ใบกำกับภาษี` → `ใบก ำกับภ าษี` |
| สระอำแตกเป็นสองตัว | `ำ` → `ํ` + `า` |
| สระหรือวรรณยุกต์หลุดไปขึ้นต้นคำ | `ใบกําักบภาีษ` |
| ข้อความถูกแต่ไม่ครบ | ภาพเต็มหน้าแต่มีข้อความแค่หัวข้อ เนื้อหาที่เหลืออยู่ในภาพ |

อาการแรกอันตรายที่สุด เพราะคนยังอ่านพอเดาออก ตัวให้คะแนนรุ่นแรกจึงปล่อยผ่าน

ระบบนี้เลือก **ถือว่าทุกอย่างเป็นภาพ** จึงไม่มีความเสี่ยงนี้ ถ้าวันหนึ่งจะเพิ่มทางลัดอ่าน text layer
ต้องมีด่านแยกสามแบบนี้ก่อน

```
ข้อความ = 0                               → PDF สแกน           → OCR
ไม่มีภาพเต็มหน้า + มีข้อความ                → PDF ดิจิทัล         → อ่านข้อความได้เลย
มีภาพคลุม ≥ 80% ของหน้า + มีข้อความ         → PDF สแกนที่ OCR แล้ว → ตรวจคุณภาพข้อความก่อน
```

ตรวจคุณภาพข้อความได้จาก สัดส่วนคำที่อยู่ในพจนานุกรม (ตัดคำด้วย PyThaiNLP), อาการเพี้ยนแบบไทยในตาราง
ข้างบน (ข้อความไทยปกติพบ 0.000 ต่อตัวอักษร เอกสารที่เสียพบ 0.010–0.024) และข้อความคลุมหมึกบนภาพได้
กี่ส่วน — โปรเจกต์รุ่นก่อนแยกเส้นทางเอกสารจริงได้ถูก 31/31 ฉบับด้วยวิธีนี้

## โครงสร้างโฟลเดอร์ข้อมูล

```
data/
├── raw/<dataset>/                    ใส่เอกสารต้นฉบับที่นี่
├── preprocess/<dataset>/<profile>/   ผล preprocess (คำสั่ง preprocess): final/ ภาพสุดท้าย, steps/ ภาพแต่ละขั้น (ใส่ --steps)
├── result_ocr/<engine>/<dataset>/    raw_data/ ข้อความดิบ (คำสั่ง ocr), final/<rules|llm>/ ผล JSON (คำสั่ง extract)
├── etc/benchmarks/ · etc/compare/    งานทดสอบ/เปรียบเทียบ (ผลวัด, เทียบรายไฟล์)
└── reports/                          รายงานภาพ
```

ถ้ารันหนึ่งครั้งมีไฟล์อินพุตมากกว่า 2 ไฟล์ ผลของแต่ละไฟล์จะอยู่ในโฟลเดอร์ย่อยชื่อไฟล์ (เช่น `raw_data/<ไฟล์>/<ไฟล์>_p1.txt`) ไม่เกิน 2 ไฟล์ก็วางตรง ๆ (ตั้งที่ `NEST_OVER` ใน `src/fin_extractor/paths.py`)
